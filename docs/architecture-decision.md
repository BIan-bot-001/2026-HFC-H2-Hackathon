# Architecture Decision

- ADR 編號：ADR-001
- 背景：活動網站內容以瀏覽、圖片與外部服務連結為主，使用期間短，使用者希望透過 GitHub 架站且不具網站維護經驗。
- 硬性政策：只能發布核准為 PUBLIC 的資料；不得將秘密放入瀏覽器或版本庫；正式部署前需 G4 明確核准；一般 GitHub Pages 不宣稱具備存取控制。

## 替代方案

1. **推薦：S1 純靜態 HTML／CSS／JavaScript＋GitHub Pages。** 無建置框架與資料庫，內容集中於設定檔，部署與回復簡單。
2. **替代：SharePoint／公司 Microsoft 365 站台。** 適合需要公司帳號登入與真正內部存取控制，但版面與匿名活動體驗較受平台限制，且需要公司權限。
3. **替代：GitHub Enterprise Cloud 私人 Pages。** 可限制為具 repository 讀取權限者，但需組織方案與帳號配置，且參與者必須具備相應 GitHub 存取權。

評分 1–5，權重沿用 skill 基準。

| 靜態站＋公開 Pages | 3 | 5 | 4 | 5 | 5 | 4 | 4.15 |
| SharePoint | 5 | 3 | 3 | 3 | 3 | 2 | 3.45 |
| 私人 Pages | 5 | 4 | 4 | 2 | 3 | 4 | 3.90 |

- 推薦理由：內容已被核准可公開，且使用者接受「公開但不主動索引、活動後取消發布」的殘餘風險；靜態方案最符合短期活動、易更新與低維運需求。
- 成本與遷移方案：目前不假設任何付費方案。若未來需要真正限制存取，可保留前端資產並遷移至 SharePoint、Azure Static Web Apps 搭配身分驗證，或符合資格的 GitHub Enterprise 私人 Pages。
- 決策者與日期：使用者，2026/11/24；G1 已核准。正式部署仍需 G4。
